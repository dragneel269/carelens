## Decisions
- Backend: uv-managed Python 3.12 non-package app layout with FastAPI, SQLModel, Uvicorn, and app/{api,core,db,domain,integration,policy,audit,seed} structure.
- Web: Vite + React 19 + TypeScript strict + Tailwind CSS v4, Fontsource fonts (Newsreader, Instrument Sans, IBM Plex Mono), shadcn/ui foundation, and TanStack Query.
- Design System (P2): Strict "Clinical Editorial" paper chart aesthetics. Self-hosted fonts; tokens mapped into Tailwind v4 `@theme`; rethemed Button, Card, Badge, Input, Tabs, Sheet (380px drawer), Tooltip, Table, Popover; built signature clinical components (`Redacted`, `MatchBadge`, `SourceBadge`, `ProvChip`, `HashChip`, `EmptyState`, `SkeletonCard`); `/design` specimen verified in Light and Dark themes.
- Backend Base & Seed Data (P3): SQLModel User table, SQLite session, Argon2 password hashing, PyJWT authentication (8-hour expiry with sub and role), POST /auth/login and GET /me, require_role RBAC dependency. Seeded all 7 users from spec §3 (password `carelens-demo`). Created 4 source datasets in native formats (EHR FHIR-like JSON, Lab JSON with local codes and mixed units, Pharmacy CSV-style rows with brand names, Insurer claims JSON) with hero patient planted discrepancies, 9 Faker patients, and 2 ambiguous pairs at seed 42. Added Section 9 LOINC and brand mappings.
- Adapters, Normalization & Ingestion (P4): Built pure source adapters (`adapt_ehr_bundle`, `adapt_lab_report`, `adapt_pharmacy_dispense`, `adapt_insurer_claim`) producing canonical `SourceRecord`, `Encounter`, `Condition`, `Allergy`, `Medication`, `Observation`, and `Claim` models. Normalized local lab codes to LOINC, unified HbA1c from both labs into % series, converted brands to generics, parsed ISO dates, retaining unmapped codes with `normalized=False`. Created idempotent `run_ingest` with `IngestReject` dead-letter queue, auto-running on startup for empty databases. Added `POST /admin/ingest` and `POST /admin/reset-demo` endpoints for admin role.
- Identity Engine & Matching (P5): Built Section 4 identity matching pipeline with name normalization (honorific stripping, vowel deduplication, symmetrical token ordering), blocking (phone match or same DOB year + Jellyfish Metaphone phonetic key), and weighted scoring (Name 0.35 via RapidFuzz, DOB 0.25, Phone 0.20, Gender 0.10, Pincode 0.10). Strict thresholds: >= 0.90 auto-link, 0.70-0.89 ReviewItem only, < 0.70 ignore. Same-system IDs always link. Single-key phone constraint enforced. Golden record synthesis (`MasterPatient` with CL-000001 IDs, Hero first) using source priority (EHR > Lab > Pharmacy > Claims) then recency, preserving per-field provenance and alternates. Per-field evidence attached to each `IdentityLink`. Clid propagated to all clinical child records. Linked `ramesh` user account by phone.
- Policy, Consent & Audit (P6): Built Section 7 zero-trust policy engine in `app/policy/engine.py` with `ROLE_MATRIX`, uncached database consent evaluation, purposeful authorization (billing = payment, others = treatment), default-deny enforcement, and clinical field redaction markers. Implemented append-only cryptographic audit ledger in `app/audit/ledger.py` with `hash = SHA-256(prev_hash + canonical_json)` and full chain integrity verification (`verify_chain`). Seeded 30-day baseline patient consents for clinicians, pharmacy, lab, and billing during ingestion. Mounted `GET /audit` (admin all, patient own), `GET /audit/verify`, `GET/POST /consents`, and `POST /consents/{id}/revoke`.
- Unified API (P7): Implemented `GET /patients?q=` with multi-attribute search (name, phone, source ID, CLID) returning `linked_systems` and `best_score`. Built `GET /patients/{clid}/unified` across demographics and clinical entities with per-category policy evaluation and field-level restricted markers. Built `GET /patients/{clid}/timeline` with type, source, and date range filters returning chronological entries. Built `GET /patients/{clid}/summary` featuring active problems, reconciled current medications with planted conflict flags (`missing_from_ehr` for Atorva 10, `allergy_conflict` for Mox 500), allergies, latest lab values with 6-point trend arrays (unifying HbA1c across labs into a single `%` series), recent encounters, and claim status. Built `GET /patients/{clid}/identity` returning all linked feeder records with per-field evidence, provenance, and alternate values. Enforced zero-trust access: doctor sees all categories, pharmacist sees only medications and allergies, billing sees only claims, and patient sees only their own linked CLID.
- App Shell & Search (P8): Completed 'Choose your badge' modal supporting all 7 user roles, calling POST /api/auth/login with 'carelens-demo' and persisting tokens in memory and sessionStorage. Implemented 3-pane layout (280px patient sidebar, flexible central canvas, 380px inspector drawer). Top bar includes 'Viewing as' role switcher (re-authenticates and refetches queries), theme toggle (light/dark paper tokens), and Cmd/Ctrl+K palette. Wired live search with MatchBadge hits (verified 'Ramesh' shows '4 systems linked - 100%'). Routes /, /patient/:id, /portal, /audit provide loading, empty, and error states. Verified via browser agent across roles and passing tests/lint.
- Patient Workspace (P9): Patient banner with name in serif 28px, master CLID and linked feeder source IDs in mono (APL-004512, LB-77120, TX-9981, PH-30991, STAR-48221), 'Consent: Treatment Active' pill, and hero 'Viewing as' role switcher. Overview tab: cards for Active Problems (with ProvChips), Reconciled Current Medications with conflict flags (Atorva missing from EHR, Mox 500 allergy conflict) and ProvChips, Documented Allergies (with ProvChips), Latest Labs with Recharts trend lines, normal reference bands (e.g. HbA1c 4.0-5.6%, glucose 70-99 mg/dL), LOINC codes, and ProvChips, and Insurance Claims with ProvChips. Timeline tab: filtered chronological list by date with SourceBadges, ProvChips, and type/source filter chips. Identity tab: linked feeder source records with plain-language 'Why linked' explanation lines and confidence scores in mono tabular format. Role switching replays a 220 ms sweep across `Redacted` bars; verified doctor, pharmacist, and billing views differ correctly via browser agent and unit tests.
- Patient Portal & Audit Table (P10): Built patient `/portal` with departmental consent directives by group (`clinicians`, `pharmacy`, `lab`, `billing`) with per-category toggle pills and quick 'Revoke All Consents' button. Built real-time access history table in calmer, larger, plainer styling displaying provider, role, declared purpose, timestamp, outcome, and prominently highlighting policy denials with alert vermilion indicator rows and denial counter filters. Built admin `/audit` ledger table with mono figures, HashChips for previous and current block hashes, and prominent 'Verify Chain' validation button confirming contiguous integrity against the genesis hash. Verified live e2e flow: revoking billing consent immediately redacts claims in billing's view, logs an append-only denial, renders the denial in patient access history, and validates cryptographic chain integrity.
- Polish + Demo Reset (P11): Built hidden `/demo` page (accessible via `Cmd+Shift+D` / `Ctrl+Shift+D` shortcut, elevated to admin) and interactive floating `ScriptOverlay` HUD adhering to `docs/demo-script.md` timestamps (0:00 through 4:40) with presenter talking points, stepper, and execution console. Connected Reset Demo Data button to `POST /api/admin/reset-demo` which wipes and deterministically reseeds all tables (seed=42) and baseline consents so hero patient CL-000001 (Ramesh Kumar) is identical after every reset. Added Pre-Warm Hero query prefetching across EHR, Lab, Pharmacy, and Claims. Implemented automated 3-consecutive-run sequence executing all 8 demo script steps across 3 complete cycles with zero page refresh. Inspected all routes in light and dark modes at 1366x768 against the anti-template design checklist. Full test suite passing (289 backend + 20 frontend) and lint clean.
- Vibrant Clinical Palette (P12): Migrated the full design system to the Vibrant Clinical palette with solid colour blocks and small accent strokes only (no gradient backgrounds behind text). Added tokens: paper #FAF7F2 / #0C1319, surface #FFFFFF / #131C24, tint-teal #E3F6F4 / #0A2E2C, ink #0F1E2B / #F0ECE1, primary #00A19B / #00C4BC, primary-strong #007F7A / #009E97, alert #FF4D3D / #FF5C4D, warn #FFB020 / #FFBA33, ok #22B573 / #2ED68B, EHR #1F6FFF / #4D8DFF, Lab #12B76A / #22D37E, Pharmacy #FF8A00 / #FFA033, Claims #E83E8C / #F065A5. Applied coloured left-edge strips on cards by source, tinted section headers, bold solid primary buttons, coloured status pills (active, pending, revoked), source-coloured markers and chips, SVG confidence progress ring on MatchBadge, vivid reference bands on lab charts, and solid vibrant avatars for roles on the login badges. Contrast verified for AA compliance across light and dark modes.
- Live Updates, Micro-Interactions, Usability & Responsiveness (P13): (1) Configured 3-second polling interval (`refetchInterval: 3000`) in TanStack Query for patient summary and timeline. Automatically detects remote consent grant/revocation transitions and displays real-time `toast.info("Access changed")`. (2) Micro-interactions built with motion respecting `useReducedMotion()`: hover & press states on buttons (`hover:-translate-y-0.5 active:translate-y-0 active:scale-[0.99]`), cards, and table rows; staggered list entrance on cards and feeds; animated count-up via `<CountUp />` component for scores, counts, and amounts; animated SVG confidence progress ring on `MatchBadge`; smooth tab transitions with `<AnimatePresence mode="wait">`; smooth drawer slide with mobile/tablet backdrop; skeleton-to-content crossfade. (3) Usability features: 5-step custom Guided Tour (`GuidedTour.tsx`) auto-launching on first login or via 'Tour' button; plain-language tooltips on every chip and badge (`ProvChip`, `SourceBadge`, `MatchBadge`, `HashChip`); comprehensive Role Cheat-Sheet dialog (`RoleCheatSheetDialog.tsx`) accessible from TopBar detailing the zero-trust RBAC matrix; visible "Why hidden: [reason]" badge alongside hatched ink bars on every `Redacted` element; global keyboard shortcut cheat-sheet dialog (`ShortcutsDialog.tsx`) triggered by `?` or TopBar button; keyboard tab navigation (`1`/`2`/`3`). (4) Responsive layout optimized down to 768px tablet width with `grid-cols-1 lg:grid-cols-2`, `min-w-0` overflow protection, and touch targets >= 40px. (5) Friendly empty and error states across all routes specifying explicit `nextStep` recovery instructions.
- Root: Cross-platform npm scripts utilizing concurrently to orchestrate backend and frontend dev, seed, test, lint, and build.
